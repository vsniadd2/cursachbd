# Flexora

> Обновление регистрации: нижеописанный режим одной общей команды заменён отдельными командами. «Бизнес» создаёт пустую команду и администратора. «Личный аккаунт» открывает `/join-team`; до подключения по коду или ссылке CRM недоступна. Код создаётся в «Команда → Добавить», одноразовый и действует 7 дней. Существующие данные сохранены в Flexora Demo. Дизайн дашборда не менялся. Фон авторизации — анимированные CSS-градиенты с текстурой, с поддержкой reduced motion.

Локальная CRM для одной команды: React + TypeScript + Express + Prisma + PostgreSQL. Все зарегистрированные пользователи работают в общей базе; доступ к действиям регулируется ролями. Это не многопользовательский SaaS с изолированными организациями.

## Запуск

Нужны Node.js 22.12+ (либо совместимая новая версия), npm и запущенный Docker Desktop.

```sh
sh scripts/start.sh
```

Скрипт создаёт `.env` с локальным случайным JWT-секретом, поднимает PostgreSQL и API, применяет миграции, заполняет демонстрационные данные и запускает frontend. Повторный запуск сохраняет данные Docker volume. Первая установка требует доступа к npm и Docker Hub.

- Интерфейс: http://127.0.0.1:5173
- API: http://localhost:3001/api/v1
- Проверка базы: http://localhost:3001/api/v1/health
- Swagger: http://localhost:3001/api/docs (OpenAPI 3.1, 32 пути API).
- Администратор демонстрационной команды: `admin@flexora.local` / `admin123`.
- Менеджер: `maya@flexora.local` / `manager123`.
- Сотрудник: `alex@flexora.local` / `employee123`.

Остановка интерфейса: Ctrl+C в его терминале. Остановка API и базы без удаления данных: `docker compose stop`. Не используйте `docker compose down -v`, если нужны сохранённые данные.

## Основной сценарий

1. Войдите администратором и создайте лид: компания, контакты, заметки.
2. Измените его статус на ACTIVE. Запись появится среди клиентов.
3. Создайте сделку с клиентом и бюджетом в USD. Перемещайте её через селектор в воронке; доступны и завершение, и отмена.
4. Создайте задачу со сделкой, исполнителем, приоритетом и сроком. Все поля и статусы можно менять.
5. Создайте счёт с уникальным номером, клиентом, суммой, валютой и сроком. Проект счёта должен принадлежать выбранному клиенту.
6. Переведите счёт в PAID. Дашборд и отчёты покажут оплату в выбранной валюте после открытия/обновления.
7. Выгрузите CSV из таблицы или отчётов. Фильтры таблиц влияют на экспорт. Импорт/экспорт клиентов в JSON находится в интеграциях.

Фильтр клиентов изначально показывает ACTIVE, лидов — LEAD; выберите «Все статусы» для полного списка. Удаление требует подтверждения; сначала удаляются связанные задачи/счета, затем сделки и клиенты.

## Аналитика

Выручка учитывает только PAID и выбранную валюту. Задолженность — SENT и OVERDUE; черновики и отменённые счета исключены. Бюджеты сделок задаются в USD. Валюты не конвертируются и не суммируются друг с другом.

График показывает шесть календарных месяцев по времени оплаты; исторические демонстрационные оплаты используют время последнего изменения. Оценка продаж = завершённые сделки / все неотменённые сделки периода. Прогноз = среднее оплаченной выручки за последние три календарных месяца, включая текущий, с учётом выбранного фильтра. Это ориентир, а не предсказательная модель.

## Дополнительные инструменты

- Кампании: сохранение названия, содержания и рабочего статуса; без выдуманных охватов.
- Email: сохраняемые темы и тексты черновиков. COMPLETED означает завершение подготовки, а не отправку письма.
- Автоматизация: активное правило уведомляет своего автора о каждой новой задаче; число запусков хранится в базе. Уведомление и задача создаются одной транзакцией.
- Колокольчик: уведомления текущего пользователя, отметка прочтения, обновление раз в 30 секунд и при открытии.
- Отзывы: сохранение в базе и личная история. Внешняя отправка отсутствует.
- Команда: роли, права, руководители, отделы, приглашения со сроком действия. Ссылку передают вручную; SMTP отсутствует. Принятие ссылки возможно при регистрации или при входе существующим аккаунтом.
- Google OAuth, SMTP, Slack и платежи не подключены. Google-кнопка отключена; тарифные карточки ведут к обратной связи. Клиентский файл JSON — действующий способ обмена данными.

## Проверки

```sh
cd frontend
npm ci
npm run lint
npm run build
npm test
npm run test:e2e
```

Браузерные тесты ожидают запущенный сайт и демонстрационного администратора. По умолчанию используют установленный Google Chrome на macOS; `playwright.config.ts` можно настроить для другой платформы. Проверяют настоящий API, создают записи с уникальными именами и удаляют их после сценария. При аварийном завершении процесса часть тестовых данных может остаться.

```sh
docker compose up -d --build
docker compose exec -T api npm run lint
docker compose exec -T api npm test
```

API-тесты запускают отдельный HTTP-listener на случайном порту и используют текущую локальную базу. Созданные ими бизнес-записи удаляются в `finally`; аудит входов сохраняется. Тесты рассчитаны на локальную демонстрационную базу с исходным администратором, не на реальную рабочую базу.

План: [docs/PRODUCT_PLAN.md](docs/PRODUCT_PLAN.md). Результаты: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

## Границы локальной версии

Нет серверного размещения, HTTPS, резервирования, multi-tenant изоляции, доставки почты, платёжного провайдера и внешних OAuth-интеграций. Refresh-токены отзываются при смене пароля; уже выданный access-токен действует до истечения своего срока. Не разворачивайте демонстрационную базу с опубликованными учётными данными в интернете.
