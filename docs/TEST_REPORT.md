# Проверка Flexora — 23 ноября 2026

## Анимации лендинга при прокрутке

Добавлены однократное появление секций через IntersectionObserver, прорисовка SVG-линии и заливки графика, рост мини-столбиков, последовательное появление карточек, задач и участников команды. Эффекты включаются только после установки наблюдателей; при reduced motion и без IntersectionObserver содержимое остаётся видимым без анимации. При фокусе с клавиатуры соответствующий блок раскрывается сразу.

Пройдены 3 браузерные проверки: основные взаимодействия лендинга; запуск и завершение прорисовки при прокрутке без повторного запуска, переключение reduced motion и мобильная ширина; доступность содержимого без IntersectionObserver. ESLint, TypeScript и сборка проходят.

## Что проверяет API-тест

- Подключение БД, запрет неавторизованного доступа, неверный пароль.
- Создание лида, перевод в клиента, создание сделки и назначенной задачи, завершение задачи.
- Создание счёта, перевод в PAID и фиксация времени оплаты.
- Ограничения роли сотрудника и немедленное применение изменений прав/деактивации к существующему access-токену.
- Конкурентная ротация refresh: один ответ 200 и один 401; logout и невозможность повторного refresh.
- Регистрация по одноразовой ссылке с назначением роли, запрет повторного принятия.
- Email-приглашение: запрет другого получателя, отмена и запрет принятия отменённого приглашения.
- Создание, переименование и удаление отделов, запрет циклов и удаления родителя.
- Активное правило действительно создаёт уведомление о новой задаче; уведомление можно прочитать.
- Сохранение и чтение личного отзыва.
- Отрицательная сумма, пробельное название, неверный UUID, испорченный JSON, конфликт номера счёта и неизвестный маршрут.
- Неверный импорт целиком отклоняется без частичного сохранения.
- Защита связанных клиентов/сделок от удаления и последующий полный CRUD cleanup.
- Проверка текущего пароля, смена пароля и повторный вход.

## Что проверяет браузер

1. Настоящий вход через форму, восстановление сессии только по refresh-токену (включая двойной bootstrap React StrictMode) → лид → клиент → сделка → задача со сроком → reload → оплаченный счёт → CSV-экспорт.
2. Открытие 23 экранов и вкладок (включая управление группами прав, отделами и приглашениями) на ширинах 1440 и 390 px. Проверка отсутствия исключений JS и горизонтального переполнения страницы. Проверка видимой ошибки при принудительном ответе API 503.
3. Создание кампании, email-черновика, правила и отзыва; сохранение после reload; импорт JSON через выбор файла, появление клиента и переключение локали на английский.
4. Создание роли, сохранение после reload, создание и переименование отдела через UI.

Скриншоты последнего прогона находятся в `frontend/test-results/dashboard-desktop.png` и `frontend/test-results/mobile-error.png`. Это временные артефакты, исключённые из Git. Вручную просмотрен скриншот дашборда.

## Unit-тесты

Пустая CRM даёт конечные нулевые значения. Оплаты и задолженность не смешиваются с черновиками/отменёнными счетами; валюты разделены; 0.10 + 0.20 даёт 0.30. Фильтр оплат использует дату оплаты, а не дату создания счёта. CSV содержит настоящий UTF-8 BOM и CRLF, экранирует кавычки, сохраняет кириллицу и переводы строк, блокирует формулы при открытии в таблицах.

## Ограничения проверки

Нет нагрузочного тестирования, отдельного аудита безопасности, полного аудита доступности, проверки Safari/Firefox и реальной отправки писем/платежей. Не проверялись все комбинации всех полей и полномочий. Google OAuth, SMTP, Slack и платежи не подключены и обозначены в интерфейсе. Кампании и письма — сохраняемые рабочие записи и черновики; охваты и доставки не выдумываются.

Данные одной команды общие. Доступ сотрудников регулируется разрешениями ресурсов; отдельные задачи не скрываются от коллег с правом tasks:read. Самостоятельная регистрация создаёт сотрудника общей команды; выбор типа аккаунта по последнему указанию пользователя не добавлялся.

API и браузерные тесты рассчитаны на локальную демонстрационную базу с исходными учётными данными. При аварийном прерывании теста возможны оставшиеся тестовые записи; известная запись от прерванного прогона удалена. Аудит входов намеренно сохраняется.
