# План переработки Flexora

Цель: развить Flexora как веб-приложение для управления клиентами и проектами IT-компании. Рабочий сценарий: **лид → сделка → клиент → проект → задачи → счёт → оплата**.

Этот файл служит рабочим планом для следующих сессий. Перед изменениями сверить состояние кода и начать с первого незавершённого пункта согласованного этапа. После проверки обновить чек-лист и кратко записать, что работает и что осталось.

## Отправная точка и решения

- Стек: React и Vite, Express, Prisma и PostgreSQL. Использовать существующие модели, сервисы и компоненты там, где они подходят.
- API уже поддерживает работу с клиентами, проектами и задачами. Счета доступны на чтение. Есть API пользователей, отделов, приглашений, ролей, разрешений и уведомлений. Перед каждым этапом сверить конкретные маршруты и проверки прав.
- Сейчас «Сделки» и «Воронка» используют проекты. Выделить сущность сделки. «Сделки» и «Воронка» станут двумя представлениями одних данных. «Проекты» получат отдельный маршрут.
- Первый релиз может сохранить лид как клиента в статусе `LEAD`. При выигрыше сделки активировать существующую карточку клиента и связать проект со сделкой. Операция должна выполняться атомарно и не создавать дубликаты при повторном запросе. Перед миграцией определить, как сохранить существующие проекты и связи.
- Серверные экраны показывают состояние API. Для функций без API использовать явно обозначенный режим «Демо» с отдельными данными. Для локального сохранения сообщать «Сохранено на этом устройстве».

## Содержание вкладок

| Вкладка | Состав и основные действия |
|---|---|
| Дашборд | Активные проекты, просроченные задачи, сумма открытых сделок, счета к оплате. График оплат, ближайшие сроки и задачи, требующие внимания. Фильтры по периоду и ответственному. Нажатие на метрику открывает список с соответствующими фильтрами. |
| Лиды | Список с источником, контактом, ответственным и ближайшим шагом. Карточка с заметками и историей. Добавление лида, назначение ответственного, создание сделки и закрытие с причиной. |
| Сделки | Таблица с суммой, этапом, менеджером и датой ожидаемого решения. Карточка с потребностью, оценкой, следующим шагом и историей этапов. Для выигранной сделки — создание или привязка проекта. |
| Воронка | Доска сделок: новая, уточнение, предложение, переговоры, выиграна, проиграна. В колонках число сделок и суммы по валютам. Смена этапа перетаскиванием и через меню. Для проигрыша указать причину. |
| Клиенты | Каталог компаний с поиском и фильтром. Внутри карточки — контакты, ответственный, заметки, сделки, проекты и счета. Создание связанных записей с подстановкой клиента. |
| Проекты | Список по сроку, статусу, руководителю и бюджету. В карточке — вкладки «Обзор», «Задачи», «Команда», «Счета», «История». Прогресс рассчитывается по задачам. Просрочка видна в списке и карточке. |
| Задачи | «Мои», «Все доступные», «Доска». Фильтры по проекту, исполнителю, сроку и статусу. В карточке — назначение, приоритет, срок, описание и комментарии. Изменение статуса обновляет прогресс проекта. |
| Аналитика | Продажи, исполнение проектов и загрузка команды. Сравнение по периоду и ответственному. Подпись объясняет расчёт метрики, переход открывает исходные записи. |
| Выручка | Реестр счетов с компанией, проектом, суммой, валютой и сроком. Отдельные суммы выставленных, оплаченных и просроченных счетов. Создание счёта и отметка оплаты доступны по правам. |
| Отчёты | Шаблоны по проектам, задачам, сделкам и счетам. Фильтры, предварительная таблица и скачивание CSV по тем же данным. |
| Прогноз | Помесячно: оплачено, ожидается по неоплаченным счетам, оценка по открытым сделкам. Для последней применяется сумма сделки × вероятность. Можно менять допущения для сценария. |
| Автоматизация | Редактор «событие → условие → действие» и предварительный прогон. Первые правила: напоминание о задаче, просрочка счёта, распределение лидов. Серверное выполнение сопровождается журналом. |
| Кампании | Список с источником, периодом, бюджетом и связанными лидами. В карточке — обращения и сделки кампании. Начать с ручной привязки. |
| Email-маркетинг | Черновики, сегмент и предпросмотр на демо. Историю реальных отправок добавить после подключения провайдера, согласий и отписки. |
| Интеграции | Каталог Jira, GitHub и Slack. Карточка с назначением, состоянием и журналом синхронизации. На демо показать пример настроек и обмена. |
| Команда | «Сотрудники», «Отделы», «Приглашения». Список и оргсхема. В карточке сотрудника — руководитель, отдел, проекты и открытые задачи. Управление составом по правам. |
| Роли и права | Самостоятельный маршрут с матрицей ролей и действий. Видно, кому назначена роль. Проверки просмотра, изменения и экспорта действуют на сервере. |
| Справка | Поиск по инструкциям для первых действий. Ссылки из инструкций открывают нужные вкладки. |
| Обратная связь | Тип обращения, описание и контекст страницы. На демо — локальный черновик. После подключения API — сохранённое обращение с номером. |
| Настройки | «Профиль», «Язык и форматы», «Уведомления», «Безопасность». Настройки команды доступны администратору. |
| Тарифы | Сравнение планов и отметка текущего. Для курсового — демо. Изменение плана зависит от подключения биллинга. |

В шапке добавить панель уведомлений. Назначение, изменение срока или просрочка ведут к записи, которая вызвала уведомление. В меню профиля — настройки и выход.

## Общие требования к интерфейсу

- Сохранить светлые поверхности, серые границы и оранжевый акцент Flexora. Цвет статуса дополняется текстом. Убрать дубликат «Активная воронка» и демонстрационную оценку продаж из рабочего дашборда при переходе на серверные показатели.
- У списков общий шаблон: заголовок и основное действие, поиск, фильтры, счётчик и данные. Фильтры хранить в URL. У ключевых сущностей есть постоянные ссылки. Быстрый просмотр открывается сбоку, на телефоне — на весь экран.
- Учесть загрузку, отсутствие записей, пустой поиск, ошибку и повторную попытку. При ошибке сохранения сохранять ввод. На время отправки блокировать повторное нажатие. Для запрещённых действий показывать состояние доступа.
- Анимации использовать для открытия панели, перемещения карточки и изменения графика. Поддержать `prefers-reduced-motion`. Проверять работу без мыши, видимый фокус и доступность основных действий на телефоне.
- Согласовать определения метрик до подключения отчётов. Суммы разных валют показывать отдельно. В списках и выгрузках применять одинаковые фильтры и права.

## Этапы реализации

- [ ] **1. Основа.** Исправить ошибки TypeScript. Создать общие компоненты таблицы, фильтров, формы, панели деталей и обратной связи. Описать права администратора, менеджера и сотрудника и сверить их с API. Ввести отдельные источники для рабочих и демонстрационных данных.
- [ ] **2. Основной сценарий.** Переработать лиды и клиентов. Добавить сделки с миграцией и связью с проектом, таблицу сделок и воронку. Реализовать карточку проекта и «Мои задачи». Проверить весь путь от создания лида до завершения задачи.
- [ ] **3. Управление.** Доработать команду, приглашения, роли и уведомления. Добавить запись счетов через API и подключить реальные показатели дашборда. Проверить, что права учитываются и в интерфейсе, и на сервере.
- [ ] **4. Аналитика и отчётность.** Подключить расчёты, фильтры, выгрузку CSV и прогноз. Сверить суммы и количество записей на всех экранах.
- [ ] **5. Дополнительные инструменты.** Оформить демонстрационные сценарии автоматизации, кампаний, email и интеграций. Доработать справку, обратную связь, настройки и тарифы.

## Проверка этапа

- Пройти изменённый сценарий из обычной навигации с подходящей ролью. Проверить ошибки, отсутствие записей и сохранение после перезагрузки.
- Проверить изменения статусов и фильтры на компьютере и телефоне. Запустить сборку и проверку TypeScript, а при изменениях API или схемы — соответствующие проверки сервера и миграций.
- Первый релиз готов, когда менеджер создаёт сделку из лида, запускает проект и назначает задачу, сотрудник завершает её из «Моих задач», а прогресс сохраняется и виден в проекте и на дашборде.

- Реализован раздел «Проекты» с реестром, доской, карточкой, сроками, командой, связанными задачами и счетами. Прежние URL сделок и воронки открывают список и доску проектов. Отдельная сущность сделки остаётся задачей этапа 2.
